# One home per setting

Decided by: agent (count the readers with `grep -rn "\.selected_model\b\|\.bindings\b\|\.paste_method\b" src-tauri/src`) · 2026-11-27

Seogi keeps two settings files: `seogi.json` (its own, `seogi/config.rs`) and the engine's store (`settings_store.json`, `settings.rs`, inherited). Each setting lives in exactly one of them, the one whose code acts on it, and is written through one path; the other side reads it there and never keeps a copy. `seogi.json` holds what Seogi's own code reads: meetings, minutes, calendars, Seogi's shortcuts, the language, and the dictation choices only Seogi reads (on/off, tidying, digits, the floating key). The store holds what the inherited engine reads at the moment it acts: the dictation shortcut and how it is pressed, the dictation model, how words are typed, sounds, fillers, how many dictations are kept, launch at login, and Seogi's two marks about the shortcut and the model (`dictation_key_moved`, `dictation_stand_in`), which sit beside the values they describe. The engine reads the language from `seogi.json` when it reads its settings (`settings::speak_seogi_language`); the store's `selected_language` is neither read nor written while Seogi runs (`write_settings` keeps what the store had). The dictation part of `seogi.json` changes only through `Secretary::update_dictation`.

Turned down: moving every setting the settings screen shows into `seogi.json`. The engine reads those values in about a hundred places (shortcuts, pasting, model loading, history), so either all of those would change, or `get_settings`/`write_settings` would quietly read and write `seogi.json` underneath the engine, which is a second path again and races with the copy of `seogi.json` the secretary holds in memory.

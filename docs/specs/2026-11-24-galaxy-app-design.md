# 서기 안드로이드(갤럭시) 앱 — 설계

2026-11-24 · 상태: 사용자 확인 대기 (검토 한 번 거침)

## 왜 만드나

서기는 기록이 필요할 때 대신 받아 적고 정리해 주고, 내가 해야 할 일(액션 리스트)을 알려 주는 앱이다. 어떤 회사와도 관련이 없는 개인 오픈소스이고, 여러 사람이 쓰면서 함께 고쳐 나가길 바란다. 피드백은 GitHub 이슈로 받는다(앱 안 '불편해요' 단추는 이슈 작성 화면을 연다).

갤럭시 기본 녹음 앱은 녹음은 잘 되지만, 그 안의 AI 가 만든 화자 구분 · 요약 · 할 일이 엉터리라 쓸 수가 없다. 사용자는 녹음을 폰으로 편하게 하고, 정리는 이미 믿을 만해진 **컴퓨터 서기의 회의록**으로 받고 싶다.
지금도 "기본 녹음 앱 → 구글 드라이브 녹음함에 손으로 올리기 → 컴퓨터 서기가 처리" 길은 있지만, 손으로 올리는 단계가 귀찮고 회의 이름도 안 붙는다.
APK 파일을 직접 나눠 주는 방식은 업데이트를 손으로 해야 해서 불편하다 → **플레이 스토어로 배포해 자동 업데이트**.

## 사용자의 큰 목표 (11/24)

**폰에서는 Typeless 를 쓰지 않고 서기만, 컴퓨터에서는 Handy 를 지우고 서기만.** 그래서 폰 앱은 녹음 앱이면서 받아쓰기(떠 있는 단추)까지 해야 한다 — 받아쓰기는 덤이 아니라 Typeless 를 대신하는 핵심 기능. **사용자 결정(11/24): 녹음과 받아쓰기 둘 다 첫 판에.** 받아쓰기 다듬기(AI)는 Typeless 만큼 빠를 때만 쓰고, 아니면 다듬지 않은 받아쓰기만(Handy 처럼). 다듬기가 실패하면 바로 원래 글을 넣는다.

## 목표

1. 폰에서 끊기지 않는 녹음 — 화면이 꺼져도, 다른 앱을 써도, 2~3시간 회의도. 강제 종료돼도 그때까지 녹음은 남는다.
2. 녹음 중 **중요 표시** 단추(시각 기록).
3. 폰 캘린더에서 지금 시각의 일정을 찾아 **회의 이름**을 자동으로 붙인다(구글 계정이 폰 캘린더에 연결돼 있으면 그대로 읽음).
4. 녹음이 끝나면 **구글 드라이브의 서기 폴더로 알아서 올린다**. 인터넷이 없으면 기다렸다가 올린다. 올린 뒤에도 폰의 원본은 지우지 않는다.
5. 컴퓨터 서기가 드라이브 API 로 그 폴더의 녹음을 직접 받아 와 지금처럼 받아쓰기 · 회의록을 만든다(2단계, 11/26 바뀜: 구글 드라이브 데스크톱 앱이 필요 없다). 회의록을 드라이브에 다시 올려 폰에서 여는 것은 다음 판.
6. 플레이 스토어 **내부 테스트** 트랙으로 팀원(초대한 사람, 100명까지)에게 배포, 업데이트는 스토어가 자동으로.

## 받아쓰기 (첫 판에 포함, 11/24 사용자 결정)

- **폰 받아쓰기 — 떠 있는 단추**(Typeless 처럼 화면 가장자리에 둥근 마이크 단추가 떠 있고, 손으로 끌어 자리를 옮길 수 있으며, 누르면 말한 것이 지금 쓰는 칸에 쳐짐) — 사용자가 원함(11/24, Typeless 화면 캡처로 보여 줌). 안드로이드 '다른 앱 위에 표시' 권한 + 글자 넣기(접근성 서비스 또는 키보드 방식). 접근성 서비스는 플레이 정책 신고가 필요하니 2단계 설계 때 키보드 방식과 견줘 고른다. 0원 원칙 때문에 음성 인식은 폰 안에서(로컬 모델 또는 폰 내장 인식) — 어떤 엔진이 한국어를 빠르고 정확하게 받는지는 조사 후 결정(계획 전 조사 단계).

### 받아쓰기 조사 결과 (11/25, 공개 문서 기준 — 갤럭시 실측 전)

- **추천**: 음성 인식 = 폰 안 sherpa-onnx + 한국어 실시간(스트리밍) Zipformer 모델(Apache 2.0, 약 125MB) — 말하는 중에 글자가 나와 1.5초 목표에 맞는 유일한 후보. 글자 넣기 = 떠 있는 단추 + 접근성 서비스(키보드는 삼성 키보드 그대로), 실패하면 복사 후 붙여넣기 안내. 최소 안드로이드 13. 다듬기 = 첫 판 끔(S25 이후 폰 내장 교정은 0.7초 안일 때만 선택 기능 후보).
- **대안**: 서기 키보드(InputMethodService) + Qwen3-ASR 0.6B(더 정확·문장부호, 약 940MB, 다 말한 뒤 계산). 접근성 신고 없음, 대신 키보드를 바꿔야 함.
- **시제품으로 먼저 확인할 위험**: ① 갤럭시 실기에서 Zipformer · Qwen3-ASR · ML Kit 한국어 정확도/속도를 Typeless 와 견주기(Zipformer 는 문장부호 없음) ② 안드로이드 14~16 에서 떠 있는 단추로 마이크가 열리는지(앱이 화면에 없을 때 마이크 서비스 제한, 재부팅 후 포함) ③ 플레이 접근성 사용 신고 통과(신고서 + 앱 안 안내·동의 + 영상; 거절되면 대안으로).
- 글자 칸이 없는 곳에서 받아쓰기만 했으면 붙여 넣지 않고 "넣을 곳이 없어요 · [복사]" 알림(Typeless 처럼, 사용자 요청 11/25). 최근 받아쓰기 몇 개는 앱 안에서 다시 복사.
- 떠 있는 단추 숨기기: 단추를 끌면 화면 아래 가운데에 × 자리가 나타나고, 거기 놓으면 '잠시 숨기기'(Typeless 와 같은 손동작, 사용자 요청 11/25). 숨긴 단추는 알림 줄이나 앱에서 다시 켬. 오래 누르면 숨기기·설정 메뉴도.
- 처음 설정은 받아쓰기만 5단계(마이크 · 알림 · 다른 앱 위에 표시 · 접근성 · 배터리 제한 없음) → 받아쓰기를 처음 켤 때만 묻고 따라하기 연습판.
- 자세한 근거: 저장소 밖 조사 보고서.

## 하지 않는 것

- 폰에서 받아쓰기 · 회의록 만들기(AI 없음). 정리는 컴퓨터 서기만 한다.
- 아이폰 앱(애플 개발자 연 $99, 지금 범위 아님).
- 정식 공개 출시(누구나 받기). 지금은 내부 테스트만.
- 회사 구글 조직(Workspace)에 클라우드 프로젝트 만들기 — 사용자가 원치 않음. 개인 계정 프로젝트로.

## 실패로 보는 것 (동작해도)

- 긴 회의 중 녹음이 조용히 끊기거나 일부가 빠짐.
- 올리기에 실패했는데 사용자가 모름.
- 폰 원본을 앱이 스스로 지움(원본은 기록 그 자체, 자동 삭제 금지).
- 녹음이 끝난 뒤 이것저것 물어 귀찮게 함.
- 유료 API 가 기본값.

## 제약

- 0원 원칙: 플레이 개발자 등록비 25달러 한 번 외에 매달 드는 돈 없음. 서버 없음.
- 구글 권한은 **`drive.file`(앱이 만든 파일만)** 하나 — 경고 화면 · 구글 심사가 없는 권한. 캘린더는 구글 API 가 아니라 폰 캘린더(CalendarContract)에서 읽는다.
- 구글 클라우드 프로젝트 · OAuth 클라이언트는 사용자 **개인 구글 계정**에 만든다. 클라이언트 정보는 공개 저장소에 넣지 않는다(빌드 때 주입).
- 저장소는 공개 오픈소스(lokim-dj/seogi). 회사 · 직원 · 고객 이름을 넣지 않는다.
- 쓰는 폰: 갤럭시(안드로이드). 최소 버전은 만드는 쪽이 정하되 최근 3년 안의 갤럭시는 되게.
- 첫 화면 전에 시안부터 — 남의 앱 모양을 베끼지 않는다. 컴퓨터 서기 A안(먹색 바탕, 빨강 포인트, 지마켓 산스 Bold 본문)과 같은 말투 · 색.

## 방법 (고려한 것)

|     | 녹음 넘기기                      | 장단점                                                                     | 결정     |
| --- | -------------------------------- | -------------------------------------------------------------------------- | -------- |
| A   | 구글 드라이브 폴더로 자동 업로드 | 현장 · 외부에서도 넘어감, 폰에서 회의록 열람 가능 / 처음 한 번 구글 로그인 | **선택** |
| B   | 같은 와이파이에서 맥으로 직접    | 구글 설정 없음 / 맥이 켜져 있고 같은 망일 때만, 폰에서 회의록 못 봄        | 안 함    |
| C   | 폰에서 직접 AI 정리              | 유료 API 필요 · 0원 원칙 위반, 정확도 검증 안 됨                           | 안 함    |

앱 만드는 방식(만드는 쪽의 판단, 사용자가 맡김): **코틀린 + Jetpack Compose 순정 안드로이드 앱**. 긴 녹음은 포그라운드 서비스로 돌려야 안전하고, Tauri 모바일 · 크로스플랫폼보다 백그라운드 녹음 · 업로드 재시도(WorkManager)를 믿을 만하게 만들기 쉽다. 저장소 안 `android/` 폴더.

## 사용자가 정한 것

- 갤럭시 앱을 만든다(컴퓨터 앱이 쓸 만해졌다고 판단).
- 배포는 플레이 스토어, 자동 업데이트(내부 테스트 트랙).
- 녹음은 구글 드라이브로 자동 업로드(A).
- 폰의 AI 정리는 필요 없음 — 정리는 컴퓨터 서기.

## 누구 컴퓨터가 처리하나 (사용자가 앞서 정함, 11/24)

**팀원마다 자기 구글 드라이브 + 자기 컴퓨터 서기.** 팀원이 폰으로 녹음하면 그 팀원 드라이브의 `서기 폰 녹음` 폴더로 올라가고, 그 팀원 컴퓨터(대개 윈도우)의 서기가 처리한다. 한 사람에게 모으지 않는다. 그래서 팀원 컴퓨터에는 서기만 있으면 되고, 설정의 '폰 녹음'에서 폰과 같은 구글 계정을 한 번 연결한다(11/26 바뀜: 드라이브 데스크톱 앱 불필요).

## 계정과 로그인 (만드는 쪽 판단)

- 폰에서 로그인하는 구글 계정 = 컴퓨터 서기에서 연결하는 구글 계정. 컴퓨터 서기는 같은 클라우드 프로젝트의 **데스크톱 앱 OAuth 클라이언트**로 `drive.file` 하나만 받는다(시스템 브라우저, `127.0.0.1` 임의 포트로 돌아오기, PKCE). 같은 프로젝트라 폰이 만든 폴더 · 파일이 보인다(11/26 실측). 클라이언트 ID · 비밀값은 빌드 때 환경 변수(`SEOGI_GOOGLE_CLIENT_ID`, `SEOGI_GOOGLE_CLIENT_SECRET`, 릴리스는 같은 이름의 저장소 시크릿)로 넣고 저장소에는 넣지 않는다. 없이 빌드하면 설정이 "이 설치판에는 구글 연결이 없다"고 말한다.
- OAuth 클라이언트는 사용자 개인 계정 프로젝트, 동의 화면 '외부'를 **프로덕션 상태**로 둔다('테스트' 상태는 7일마다 로그인이 풀려 업로드가 조용히 멈춤 → 실패 기준 위반). `drive.file` 하나뿐이라 구글 심사 없음.
- 위험: 회사 관리자가 '확인되지 않은 외부 앱' 로그인을 막아 두었으면 회사 계정 로그인이 거절된다. 그때는 화면에 이유를 보여 주고, 관리자에게 이 앱 하나만 허용해 달라고 부탁하는 길을 안내한다.

## 폰 원본 위치 (만드는 쪽 판단)

공용 저장소 `Recordings/서기/`(MediaStore)에 둔다 — 앱을 지워도 원본이 남고 '내 파일'에서 보인다(원본 보존 원칙). 사용자가 직접 옮기거나 지운 파일은 앱이 되살리지 않고 목록에 '폰에 없음'으로 표시한다. 녹음 중 조각도 같은 곳의 숨김 하위 폴더에 두어 강제 종료 뒤 되살린다.

## 드라이브 폴더 (만드는 쪽 판단, 사용자 확인 필요 없음)

`drive.file` 권한은 앱이 만든 파일 · 폴더만 볼 수 있어서, 사용자가 이미 만든 '녹음함' 폴더에는 바로 쓸 수 없다. 그래서:

- 앱이 내 드라이브에 **`서기 폰 녹음`** 폴더를 스스로 만들고 거기 올린다.
- 컴퓨터 서기는 폴더를 이름이 아니라 표시(`appProperties seogi=recordings-root`)로 찾고, 폰보다 먼저 연결되면 폰과 똑같이 만들어 둔다(나중에 폰이 같은 폴더를 쓴다). 앱을 켤 때, 켜져 있는 동안 5분마다, '지금 가져오기'를 누를 때 본다.
- 녹음은 **온전한 짝만** 가져온다: m4a 와 JSON 이 둘 다 있고, 받은 소리 파일의 SHA-256 이 JSON 의 값(되살린 녹음처럼 JSON 에 값이 없으면 드라이브가 계산한 값)과 같을 때만. JSON 만 있거나 소리만 있으면 다음에 다시 본다. 회의 제목은 JSON 의 일정 제목, 시작 시각은 `started_at`, 중요 표시는 `marks_ms`.
- 같은 녹음을 두 번 가져오지 않는다(드라이브 파일 ID + SHA-256 을 장부에). 드라이브의 파일은 고치지도 지우지도 않는다. 회의를 휴지통에 버리면 다시 가져오지 않는다.
- 폰 앱 회의 목록에서 회의를 누르면 드라이브 앱으로 그 폴더/회의록을 연다(앱 안 회의록 보기는 다음 판).

## 화면 (시안 먼저)

1. 처음 실행: 마이크 · 알림 · 캘린더 권한 → 구글로 로그인(드라이브) → 끝. 각 단계 왜 필요한지 한 줄.
2. 홈: 큰 녹음 단추 + 다음 일정 한 줄 + 최근 녹음 목록(올림 상태: 기다림 / 올리는 중 / 올림 / 실패 · 다시).
3. 녹음 중: 시간, 소리 막대, 중요 표시, 끝내기. 잠금 화면 알림에서도 중요 표시 · 끝내기.
4. 설정: 구글 계정, 음질(기본 권장), 와이파이에서만 올리기(기본 끔), 정보 · 버전.

## 녹음 파일

- 형식은 컴퓨터 서기가 읽는 것(m4a/AAC 모노 권장, 음성용 비트레이트). 긴 녹음은 끊김 대비로 조각 저장 후 합치거나, 강제 종료 때도 앞부분이 살아 있는 방식.
- 같이 올리는 작은 JSON(녹음 시작 시각 · 길이 · 중요 표시 시각 · 캘린더 일정 제목 · 기기 정보 · SHA-256). 컴퓨터 서기가 읽어 회의 이름 · 중요 표시에 쓴다(컴퓨터 쪽에 읽는 코드 추가).
- 파일 이름: `YYYY-MM-DD HHMM 일정제목.m4a`(일정 없으면 시각만).

## 만드는 쪽에 맡기는 것

- 안드로이드 최소 버전, 라이브러리 고르기, 녹음 조각 방식, 업로드 재시도 간격.
- 앱 아이콘(컴퓨터 서기와 같은 계열).
- 패키지 이름(`io.github.lokimdj.seogi` 계열).

## 사람이 손으로 해야 하는 것 (만들기 전에 알림)

1. 맥에 안드로이드 개발 도구 받기(JDK · 안드로이드 SDK, 수 GB) — 받기 전에 사용자 허락.
2. 사용자 개인 구글 계정으로 구글 클라우드 프로젝트 · 안드로이드 OAuth 클라이언트 만들기(2단계 인증 필요) — 단계표 제공.
3. 플레이 콘솔 개발자 등록(25달러, 신분 확인) — 사용자가 직접 결제.
4. 갤럭시에서 시험: USB 디버깅 켜기 또는 내부 테스트 링크로 설치.
